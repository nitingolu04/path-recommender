## Prompt

I'm building a prototype called **"AI-Powered Personalized Learning Path Recommender"** for a hackathon-style challenge. Set up the full project structure and implement it step by step. Here's the spec:

### Goal
Build a web app where a user describes a learning goal in natural language (e.g. "I want to become a data analyst, I know some Excel"), and the app returns a personalized, sequenced learning path of courses with explanations, plus a progress dashboard.

### Tech stack
- **Backend:** Python, FastAPI
- **Frontend:** Streamlit (single-app, fast to build, good for a 1-week prototype)
- **ML:** `sentence-transformers` library, model `all-MiniLM-L6-v2`, used for embedding course descriptions and user goals, ranked via cosine similarity
- **Database:** SQLite (via `sqlite3` or `SQLAlchemy`) to store user profiles, progress, and feedback
- **Data:** A local CSV course catalog (`data/courses.csv`) with columns: `course_id, title, description, skills, prerequisites, difficulty_level, category`

### Architecture — implement these 5 components as separate modules

1. **`chat_interface`** — Streamlit text input where the user types their goal in natural language. Sends raw text to the profiling engine.

2. **`profiling_engine`** — Converts raw user text into a structured profile:
   ```json
   {
     "goal": "string",
     "current_skills": ["list of skills mentioned"],
     "experience_level": "beginner | intermediate | advanced",
     "interests": ["list of domain interests"]
   }
   ```
   Use a **hybrid approach**:
   - Rule-based / keyword matching: check the user's text against the known skill list from the course catalog
   - Embedding-based: embed the user's stated goal, compare via cosine similarity against pre-embedded category labels (e.g. "data science", "web development", "UX design") to classify domain
   - Persist the profile in SQLite keyed by a session ID

3. **`recommendation_engine`** — Core ML component:
   - On startup, embed all course descriptions once using `all-MiniLM-L6-v2` and cache the vectors (don't recompute every request)
   - Embed the user's goal + interests from their profile
   - Rank all courses by cosine similarity
   - Return the top N candidate courses
   - Log/return the similarity score per course (needed for the explainer)

4. **`path_generator`** — Takes the top candidate courses and orders them:
   - Rule-based: topological sort using each course's `prerequisites` field against `difficulty_level` (beginner → intermediate → advanced)
   - Insert 2-3 milestone checkpoints in the sequence (e.g. "complete first 3 courses → suggest a project")
   - Output an ordered list of course objects with a `step_number`

5. **`explainer`** — For each recommended course, generate a short natural-language reason using a template filled with data from the profile + similarity score, e.g.:
   `"Recommended because it matches your interest in {interest} and builds on your {skill} experience."`
   Also implement a simple Q&A function: given a user question like "why this course?" or "what if I already know Python?", look up the relevant course/profile data and respond using templates (no need for an external LLM API — keep it self-contained).

6. **`dashboard`** — Streamlit page showing:
   - Progress bar / percentage of path completed
   - List of skills gained so far
   - Next recommended action
   - Feedback buttons per course ("too easy" / "not interested") that update the user's profile in SQLite and trigger re-ranking via the recommendation engine

### Data
Generate a synthetic but realistic `data/courses.csv` with ~150-200 rows across 4-5 categories (Data Science, Web Development, UX/UI Design, Business/Marketing, Cloud/DevOps). Each row needs: `course_id, title, description (2-3 sentences), skills (comma-separated), prerequisites (comma-separated course_ids or empty), difficulty_level (beginner/intermediate/advanced), category`.
